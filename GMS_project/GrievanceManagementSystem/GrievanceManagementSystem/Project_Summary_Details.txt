Controller files (Controllers/)
-------------------------------
1) DashboardController.cs.cs
   - Namespace: GrievanceManagementSystem.Controlllers (note the typo: "Controlllers" with 3 l's)
   - Action: Index() -> returns View()
   - File name includes an extra ".cs" in the filename (DashboardController.cs.cs). Consider renaming to DashboardController.cs and fixing the namespace.

2) RoleController.cs
   - Constructor injects: IRoleService
   - Actions:
	 - Index() -> returns a view with _roleService.GetAllRoles()
	 - Create() [GET] -> returns view
	 - Create(RoleViewModel role) [POST] -> validates ModelState and calls _roleService.AddRole(role); sets TempData["Success"]; redirects to Index
   - Uses GrievanceManagementSystem.ViewModels.RoleViewModel

3) DepartmentController.cs
   - Constructor injects: IDepartmentService
   - Actions:
	 - Index() -> uses _departmentService.GetAllDepartments() and passes to view
	 - Create() [GET] -> returns view
	 - Create(DepartmentViewModel department) [POST] -> validates ModelState, calls _departmentService.AddDepartment(department); sets TempData["Success"]; redirects to Index

Note: Controllers reference services (IRoleService, IDepartmentService) that are implemented in Services/ as singletons and registered in Program.cs.

Services (Services/)
--------------------
- IRoleService.cs: defines methods
  - List<RoleViewModel> GetAllRoles();
  - RoleViewModel GetRoleById(int id);
  - void AddRole(RoleViewModel role);
  - void UpdateRole(RoleViewModel role);
  - void DeleteRole(int id);

- RoleService.cs: in-memory implementation with a static List<RoleViewModel> roles; seeded with one Admin role. Implements GetAllRoles, GetRoleById, AddRole (auto-increments RoleId), UpdateRole, DeleteRole.

- IDepartmentService.cs: defines analogous methods for departments.

- DepartmentService.cs: in-memory implementation with a static List<DepartmentViewModel> seeded with IT and HR entries. Implements GetAllDepartments, GetDepartmentById, AddDepartment (auto-increments DepartmentId), UpdateDepartment, DeleteDepartment.

- Views/Role/
  - Index.cshtml: strongly-typed view model IEnumerable<RoleViewModel> that renders a table of roles (ID, Role, Description, Status with bootstrap badges). Uses TempData["Success"] to show messages.
  - Index.cshtml.cs: Razor Page PageModel stub
  - Create.cshtml: form for adding a role. The file header has @model GMSRole (Model class) — this is inconsistent with RoleController which expects RoleViewModel in POST. Create.cshtml.cs exists as a PageModel stub (empty).

- Views/Department/
  - Index.cshtml: has @page and is a Page template (very small)
  - Create.cshtml: has @page and is a Page template (very small)
  - Both have corresponding Create.cshtml.cs and Index.cshtml.cs PageModel stubs

Notes about view type inconsistencies
- Some views are Razor Page style (@page + PageModel files in Views/*) and some are MVC Razor views (Views/Role/Index.cshtml and Views/Role/Create.cshtml are MVC style using controller actions). The mix of patterns may lead to confusion. Choose between MVC or Razor Pages and standardize.
- Views/Role/Create.cshtml sets @model GMSRole but the RoleController POST expects RoleViewModel. Either modify the view to use RoleViewModel or update the controller to accept GMSRole.
